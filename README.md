## About This Project

In this project, I use my own HomeLab to work on common IT support and system administration problems. I use the Windows, Microsoft 365, Linux, and Docker environment that I set up in the previous parts of my IT-HomeLab Series.

For each case, I create a ticket in GLPI. I investigate the problem, look for the cause, apply a solution, and test the result. I record my work in GLPI and share the main steps and useful screenshots here on GitHub.

I simulate all cases in my own HomeLab. I choose problems that IT support staff and system administrators often deal with at work.

## My Goals

I want to keep my IT skills up to date, gain more hands-on experience, and prepare for daily work in an IT team in Germany.

I focus on understanding problems, checking possible causes, and explaining my decisions. I also practise writing clear ticket notes and communicating with users in German.

I use requirements from IT support and system administrator job advertisements to help me choose useful topics. Here, I show how I work through each problem and what I find along the way.

## Language

I write this overview and the short case summaries in **English**.

I write the detailed case pages, GLPI ticket notes, and user messages in **German**. This helps me prepare for technical work and everyday communication in an IT team in Germany.

## How I Work on Each Case

1. I create a GLPI ticket with the user's problem or request.
2. I check who and what the problem affects, choose a category, and set the priority.
3. I ask questions, check settings and logs, and test possible causes.
4. I apply a solution and record what I change.
5. I test the result with the affected user account and check whether the original problem is gone.
6. I write a short message to the user and close the ticket after checking the result from the user's side.

In these simulations, I take both the user and technician roles. If I cannot fully solve a problem, I explain what I tried and what I would check next or pass on to another team.

On each case page, I describe the problem, my checks, the cause, the solution, and the final test. I add useful commands, screenshots, and a short note about what I learned. I keep passwords, tokens, and personal data out of the screenshots and notes I share.
